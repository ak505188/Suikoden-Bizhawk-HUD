# Static Monster/Boss AI Catalog

Generated by `scripts/ScanMonsterRecords.py`, which walks every file under the unpacked
disc's `data/` tree looking for byte-valid `MonsterRecord` structs — a charmap-decodable
name, stats in sane ranges, and a `pAiFunction` pointer landing inside that same file's
own mapped `0x80010000+` range. No live emulator session is needed for any of this: import
the file into Ghidra at base `0x80010000` (`PSX:LE:32:default`), then `create_function` at
the listed AI address and decompile directly.

This complements `lib/EncounterTable.lua` (the Lua-side, live-memory-reconstructed random
encounter rosters). Cross-referencing the two is what turns a raw file scan into an actual
area map: each area's overlay hosts BOTH its full `EncounterTable.lua` random roster AND
any scripted bosses for that area — the bosses just don't appear in `EncounterTable.lua`
since that file only tracks random encounters.

**Live-memory counterpart**: the same `MonsterRecord` struct this scanner finds offline is
also reachable live during a real battle, per-slot, with no file scanning at all —
`BattleState.pAttackDataTable[bId]` (see
[Turn_Order.md](./Turn_Order.md#finding-a-living-enemys-move-choice-probability-per-instance))
resolves directly to this same record. Useful when you already have a live battle and just
need "which monster is in this slot and where's its data"; this catalog is still the right
tool for "what monsters exist and what are their base stats" without needing a savestate
for every single one.

**Caveat**: this only finds overlay files laid out as a single flat, uncompressed block
(true for every file below). `vc61.bin` ("Dragon") is the one confirmed exception found so
far — its monster record is plaintext but its AI code is not directly readable at the
naive offset; see [../../notes/Battle_Damage_Formula.md](../../notes/Battle_Damage_Formula.md)
before assuming this technique works on every file.

One AI pointer is frequently reused across several regular random-encounter records within
the same file (e.g. `0x80010004` in `va2.bin`/`vb1.bin`/`vz2.bin`/`vz3.bin` for all
"Empire Captain"/"Empire Soldier" variants) — that's expected: many trash mobs share one
generic "basic melee, roll `rand()%100` to pick a target" routine (see the Eagle
Man/Death Boar finding below). A *repeated* AI address across very different monsters is a
signal of a shared generic routine, not a bug in the scan.

## By area folder

### `01_area.a`
- **`va4.bin`** (443028 bytes) — Magician's Island roster: FurFur (`0x800100b8`), Holly Boy
  (`0x80010a7c`), plus its own scripted boss: **Golem** (`0x80010ea4`, lvl12 HP300) —
  Magician's Island's own boss, just missing from `EncounterTable.lua`'s roster (which only
  tracks random encounters).
- **`va7.bin`** (399040 bytes) — Mt. Seifu roster: Soldier Ant, Bandit (×3 records — the
  "Bandit R/Y/G" color suffixes in `EncounterTable.lua` are Lua-side, all three are just
  "Bandit" in the data, all sharing AI `0x800103b0`), Black Wild Boar. Plus Mt. Seifu's own
  scripted boss cast: **Varkas** (`0x800103b0`, lvl12 HP210 — reuses the plain-Bandit AI
  routine), **Sydonia** (`0x8001234c`, lvl10 HP140, own unique AI), and a **scripted Queen
  Ant** fight (`0x80010ae0`, lvl15 HP7000) — this is a genuinely different encounter from
  Seek Valley's Queen Ant below, not a weaker/earlier version of the same fight; the two
  just share a name and sprite.
- **`va8.bin`** (253160 bytes) — Mt. Tigerwolf roster: Killer Slime, Slasher Rabbit, Giant
  Snail. No extras found.
- `va2.bin`/`va3.bin` — Empire Captain/Soldier records only (not tied to any
  `EncounterTable.lua` area — likely an early scripted Imperial-army sequence).

  Ghost Armor, Oannes, Giant Slug. No extras.

  scripted encounter.
- **`vb5g.bin`** (288672 bytes) — **Zombie Dragon** (`0x80012968`, lvl30 HP3700) — already
  fully documented in `Battle_Damage_Formula.md`/`Scripted_Battle_Actions.md`.
- **`vb6.bin`** (458655 bytes) — Great Forest roster: Kobold (×2), Holly Spirit, Holly Boy.
  Extra: unlisted Veteran Soldier record.
- **`vb8.bin`** (144024 bytes) — three isolated named-human bosses with no random roster in
  the file at all: **Anji** (`0x80010004`, lvl39 HP1700), **Kanak** (`0x80010004`, lvl35
  HP2200), **Leonardo** (`0x80010004`, lvl36 HP1400) — all three share one AI pointer,
  suggesting a shared "elite human duelist" generic AI rather than custom scripts each.
  This is the scripted fight for recruiting them.
